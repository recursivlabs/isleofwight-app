## 1. The headline

**Three REST route groups are 403-dead in production right now, and I confirmed it with a live request, not a code read** — `/evidence` and `/moderation` return `no_scopes` to an *unauthenticated* caller while `/projects` correctly returns `missing_api_key`, which is the signature of a route mounted without its auth middleware; the cause is that `/signals`, `/evidence` and `/moderation` are mounted at `recursiv: packages/server/src/features/api-keys/rest/index.ts:333,365,372` but appear nowhere in the parallel `api.use()` list at `:254-321`, and `git log -S` dates `/signals` to **9 weeks ago** (`782f732b`), meaning every Minds product signal has been dropped for two months while `signal` is a ×3 term in this very formula. **Second — and this is new since the last draft — I broke our own billing API by dogfooding it:** `mcp__recursiv__get_billing_usage(year=2026, month=7)` returned `"period_start": "2026-08-01"`, because the MCP declares month as 1-12 (`recursiv: packages/mcp/src/tools/devtools.ts:60`, `z.number().int().min(1).max(12)`) while the REST handler behind it is 0-indexed (`billing.ts:33`, `min(0).max(11)`, feeding `Date.UTC(year, month, 1)` at `:383,438,485,529`) — so **every MCP billing query returns the wrong month and December is unqueryable**, which I also proved live (`month=12` → `Invalid year or month parameter`). **Third, Bill's supersession thesis is real but far narrower than expected**: only two clean kills (seven hand-rolled Chrome DevTools Protocol WebSocket clients, now covered by `mcp__claude-in-chrome__*`; and `minds: lib/useVoiceRecorder.ts`, covered by `expo-audio`) plus one strategic retreat (`recursiv chat`), while the localhost tunnel, the dispatcher, `run_sql_query`, evidence/evals and the 9 protocol adapters have **no external replacement at all**. **Fourth, the org-invite flow is landing invitees on a screen that ignores the invite:** the platform documents `<customer-app>/sign-in?code=…&email=…` as the canonical accept URL (`recursiv: organizations.router.ts:696-705`, `rest/routes/organizations.ts:879`), but neither the provisioning scaffold's sign-in (`recursiv: packages/server/src/features/vibe/template/slim-app/app/(auth)/sign-in.tsx`) nor Minds' (`minds: app/(auth)/sign-in.tsx`) parses either parameter — both demand a password the invitee never set. **Fifth, the `@recursiv/client` question is now resolved and it resolves against deprecation**: `apps/mobile/App.tsx:4` and `apps/demo/App.tsx:3` both import `RecursivProvider, NavigationSetup, router` from it, `apps/mobile` is the deployed flagship (`preview-deploy.yml:234`, `staging-deploy.yml:105`) and is guarded by `visual-regression.yml:7` — so `packages/client` has two live consumers and #37 stays a consolidation, not a kill.

**Dogfooding note.** The audit ran through our own MCP and our own MCP produced two of the findings above. `mcp__recursiv__whoami` → `{"scope_mode":"scoped","tools_available":205,"tools_hidden":36}` across exactly 33 scopes — reconciling exactly to the 36 `admin_*` registrations I extracted by script (205 + 36 = 241). `get_dispatcher_stats` → 2,260 tasks / 327 done / 1,985 archived. `list_protocols` → 9 adapters. `list_orgs` → real org rows. `get_billing_usage` → **wrong month, live** (item #12). `browser_inspect_page` on recursiv.io → correct structured summary but an unreadable container `screenshotPath`. `list_signals` → 5 real rows **via MCP while the REST `/signals` group is 403-dead**, which is itself the proof that the two surfaces have diverged. Four of our own tools failed us mid-audit: `browser_screenshot` (unusable output), `run_visual_audit` (needs a deployed base_url), `get_billing_usage` (wrong month), and `run_sql_query` (**cannot reach the control plane** — its live schema requires `project_id` and its description reads "against a project's database", which invalidated an A-bar in the previous draft; see #30). - **`try_code` is NOT superseded by `execute_code`.** `recursiv: packages/mcp/src/tools/sandbox.ts:15` takes `anonClient`, and `createServer.ts:81` passes the **anonymous** client — `try_code` is the *unauthenticated try-it-now* path. `execute_code` (`projects.ts:270`) is scoped and billed. `registerSandboxTools` returns early at `sandbox.ts:16-18` unless explicitly opted in, and `tools/__tests__/sandbox.test.ts:40,44` tests **both** paths — a regression test *for the fail-closed guard*. - **`minds: lib/audio/engine.ts` must NOT be deleted.** `lib/audioPlayer.tsx:11` does `import engine from './audio/engine'`, and `grep -rn moduleSuffixes` across Minds returns **zero hits**, so `tsc` has no knowledge of Metro's `.native.ts` resolution and binds that import to `engine.ts` specifically. Deleting it red-lines `pnpm typecheck`, which `minds: .github/workflows/ci.yml:25` runs on every PR — the same gate #4 is unblocking. **The actual defect is the docblock:** `engine.ts:1-21` says track-player *"can't run in Expo Go"* and instructs `npx expo install react-native-track-player`, already pinned at `minds: package.json:56` (`^4.1.2`), already patched (`patches/react-native-track-player@4.1.2.patch`, commit a64fe33), with a complete **97-line** `engine.native.ts`. Fix the words, keep the file.
- **`react-native-track-player` itself** carries that hand-maintained RN 0.81 Kotlin patch. expo-audio does **not** yet match it on lock-screen / Control Center / Android foreground-service playback. Ripping it out loses capability. **Investigate (#60), do not migrate.**
- **`run_sql_query`** (`recursiv: devtools.ts:285`) *looks* like an obvious Postgres-MCP target and is not: SELECT-only anchor, comment stripping, string-literal stripping before keyword scan, multi-statement rejection, 10KB cap, 1000-row truncation, 30s timeout. Generic Postgres MCPs hand a model a raw connection. **Ours is the better tool** — though note it is deliberately *scoped to provisioned project databases only* (live schema this session: `project_id` required), which is why it cannot answer control-plane questions.
- **Composio integrations** (`recursiv: devtools.ts:762-799`, ~110 apps). My own session has first-party Gmail/Slack/Drive/Calendar/Vercel connectors — so for a *human driving Claude*, ours adds nothing. ## 6. Ranked priorities — the DO list

**Formula, transcribed verbatim from `DispatcherService.ts:118-176`:**
```
score = ((proximity × milestone_mult) + (leverage × 3) + (signal × 3) + (urgency × 3)
       + (severity × 8) + (ui_impact × 5) + (revenue × 7) + (growth × 5) + (mission × 4))
       / max(sqrt(effort), 1)
```
**Conventions, stated so the numbers reproduce:** `milestone_mult = 2.0` (**R2**) applied uniformly to all 63 rows. `leverage = blocksCount`, shown as **L**. Columns: **P**=proximity 1-10 · **L**=leverage/blocks · **S**=signal 0-5 · **U**=urgency 0-5 · **Sev**=severity 0-5 · **UI**=ui_impact 0-5 · **R**=revenue 0-10 · **G**=growth 0-10 · **M**=mission 0-10 · **E**=effort · **Num**=numerator, so the arithmetic is `Num / sqrt(E)`.

> ⚠️ **create_task warning:** `MILESTONE_MULTIPLIERS[milestone ?? ''] ?? 0.5` (`DispatcherService.ts:161`). Create these **with** `milestone: "R2"` or every proximity term drops to a quarter of what is shown and the ranking scrambles.
