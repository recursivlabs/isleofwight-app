list of things that **do not** happen. No command can prove a named route is unscreened, so the

### What exists instead, and why it is not screening

`packages/server/src/features/moderation/moderationService.ts` is **123 lines** and its exported
surface is `applyAction` and `reverseAction` — it **applies and reverses enforcement decisions that
something else has already made.** Its only callers are:

```
$ git -C /home/bill/dev/recursiv grep -ln "moderationService" origin/main -- 'packages/server/src'
packages/server/src/features/api-keys/rest/routes/moderation.ts   # admin-triggered
packages/server/src/features/api-keys/rest/routes/reports.ts      # user-report-triggered
```

**Both entry points are post-hoc and human-initiated.** Nothing runs at ingest. Nothing runs at
publish. A post containing anything at all is published first and can only be actioned afterwards,
by an admin or in response to a user report.

### The content-bearing write routes, named — the ones this gap actually matters on

Enumerated from (a), not from memory. Each is a path by which user-supplied content enters the
system with **no automated screening between submission and visibility**:

| Route | What enters | Reachable by |
|---|---|---|
| `POST /posts` | post bodies, media references | any authenticated user |
| `POST /posts/:id/reactions` | reaction payloads | any authenticated user |
| `POST /uploads/*`, `POST /storage/upload-url` | binary media, via presigned PUT | any authenticated user |
| `POST /chat/dm`, `/chat/messages`, `/chat/conversations/group` | private message content | any authenticated user |
| `POST /chat/messages/as-agent`, `/agents/:id/messages`, `/agents/:id/chat` | agent-authored content | agent keys |
| `POST /signals/post` | protocol-ingest signal payloads | scoped keys |
| `POST /protocols/refresh` | federated inbound content | scoped keys |
| `POST /brain/message` | agent-directed content | authenticated |

**The media path is the sharpest case.** `POST /storage/upload-url` issues a **presigned URL** and
the bytes are then PUT directly to storage by the client — so the platform never sees the payload
in a request it could screen, even in principle, without a post-upload hook. Any screening design
that assumes it can inspect an upload inline is wrong about this surface.
